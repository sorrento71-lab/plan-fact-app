# План-Факт

Система учёта рабочего времени «план-факт» для производственного участка:
график (план) сверяется с фактическими явками из журнала СКУД, формируются
табель Т-13, отчёты за неделю/месяц и выгрузка «Питание».

## Структура

```
backend/    — FastAPI-приложение (бэкенд) + SQLite БД (plan_fact.db)
frontend/   — React-приложение (Material UI)
start.bat   — запуск бэкенда и фронтенда; stop.bat — остановка
requirements.txt — зависимости Python
*.xlsx      — исходные данные (график, план-факт) и шаблоны
```

## Запуск

Проще всего — двойной клик по `start.bat`:
1. поднимается бэкенд (FastAPI) на `http://127.0.0.1:8000`;
2. запускается dev-сервер фронтенда на `http://127.0.0.1:3000`.

Скрипт сам проверяет зависимости, устанавливает их при необходимости
и не запускает повторно уже работающие серверы. Остановка — `stop.bat`.

Вручную:

```bat
cd backend
py -m uvicorn app:app --reload          :: бэкенд на :8000
```

```bat
cd frontend
npm install                              :: один раз
npm start                                :: дев-сервер на :3000
```

## Работа в сети и перенос на другой компьютер

- **Остальные участники** открывают программу в браузере по адресу `http://<адрес сервера>:3000`
  — ничего устанавливать им не нужно. Компьютер-сервер должен быть включён, а его адрес лучше
  закрепить (постоянный IP или имя). Разрешать адреса вручную больше не нужно: бэкенд сам
  разрешает localhost, собственные адреса машины, частные диапазоны (10.x, 172.16–31.x, 192.168.x)
  и имена без домена. При первом запуске Windows может спросить разрешение в брандмауэре — разрешите.
- **Настольная сборка** `desktop-a\dist\План-Факт\План-Факт.exe` — то же приложение отдельным окном,
  **Python и Node.js не нужны**. Она тоже слушает все интерфейсы, поэтому окно доступно и с других
  машин по тому же адресу. Если exe лежит внутри папки проекта, он работает с теми же данными, что
  и веб-версия (`backend\plan_fact.db`, `ГРАФИК_ФОРМА A3.xlsx`); при переносе отдельной папкой —
  со встроенной копией. Только этот компьютер: ключ `--local-only`.
- **Перенос на другой компьютер.** Вариант 1: поставить Python 3.14 и Node.js, скопировать папку
  без `.venv` и `frontend\node_modules` и запустить `start.bat` — зависимости установятся сами
  (`requirements.txt` и `npm install`). Вариант 2: перенести настольную сборку целиком.
  Данные — это `backend\plan_fact.db`, `ГРАФИК_ФОРМА A3.xlsx` и папка `backup\`.

## Загрузка данных

- **График** — `POST /upload/schedule/` (файл вида «ГРАФИК_ФОРМА A3.xlsx»);
- **Журнал явок** — `POST /upload/journal/` (выгрузка из СКУД, `tc-tmp*.xls`);
- **Питание** — `POST /export/meal/` с файлом `backend/Питание.xlsx`.

## Репозиторий (GitHub)

- В репозиторий попадают только код и **пустые формы** из папки `samples/`.
  Файлы с ФИО сотрудников (график, табели, план-факт) и база `backend/plan_fact.db`
  исключены через `.gitignore` — репозиторий публичный, персональные данные в него не заливаются.
- Развернуть проект из репозитория: скопировать формы из `samples/` по местам
  (см. `samples/README.md`), затем `start.bat`.
- Пересобрать пустые формы из рабочих файлов: `.venv\Scripts\python.exe tools\git-prep\make_empty_samples.py`.

## Коды смен

| Период | Основная смена | Доп смена | Отпуск / больничный / б/с |
|---|---|---|---|
| до 31.10.2026 | `11` (2 через 2), `9` и `8` (5 через 2) | `Д` | `О` / `Б` / `б/с` |
| с 01.11.2026 | `Я` | `В` | `О` / `Б` / `б/с` |

- Точка смены схемы одна: `backend/shift_codes.py` (`NEW_SCHEME_START = 01.11.2026`).
  Все зависимости (правка ячеек, импорт плана, перенос план↔график, расстановка по ритму,
  очистка, план-факт, табель, медосмотр) приводят значения к схеме месяца через этот модуль.
- Часы плана: `11`/`9`/`8` — по длительности, `Д`, `Я`, `В` — 11 ч.
- В графике `В` (доп смена) красится жёлтым, как раньше `Д`; `Я` — без заливки, как `11`/`9`/`8`.
- Ритм для расстановки смен: до ноября код задавал цикл (`11` — 2 через 2, `9` и `8` — 5 через 2),
  с ноября цикл подбирается по фактическому рисунку месяца (2 через 2 или 5 через 2).
- В табеле Т-13 `В` больше **не** выходной: дни с планом `Я` и `В` показываются как `я`,
  выходной — пустая клетка.
- Данные за ноябрь (лист `11.2026` и план в базе) переведены на `Я`/`В`;
  инструменты миграции и проверки — `tools/shift-codes-migration/`.

## Основные эндпоинты

| Метод | Путь | Описание |
|---|---|---|
| GET | `/plan-fact/?year=2026&month=8` | Сводка план-факт |
| GET | `/timesheet/` | Данные табеля Т-13 |
| GET | `/export/timesheet/` | Выгрузка табеля Т-13 (xlsx) |
| GET | `/export/weekly/?week_id=N` | Выгрузка недели |
| GET | `/export/monthly/?year=&month=` | Выгрузка месяца |
| POST | `/update-time/` | Приход/уход |
| POST | `/update-production-stage/` | Этап производства |
| POST | `/clear-week/` | Очистка недели (год/месяц — параметры, по умолчанию текущие) |
| GET | `/stats`, `/health` | Служебные |

Полный список — в корне API: `GET /`.

## База данных

SQLite-файл: `backend/plan_fact.db`. Путь задан относительно `backend/database.py`,
поэтому БД не зависит от того, из какой папки запущен сервер.
