# План-Факт — прототип «вариант А» (отдельное окно, без браузера)

То же самое приложение «План-Факт», но открывающееся **как отдельная программа в своём
окне**: без браузерных вкладок, без адресной строки, без `localhost:3000` в строке адреса.

Код существующего приложения при этом **не изменён вообще**: ни `backend/`, ни
`frontend/`, ни конфиги. Всё новое находится только в этой папке (`desktop-a/`).

---

## 1. Чем это отличается от обычного запуска

| | Обычный запуск (`start.bat` в корне) | Прототип «вариант А» (`desktop-a\start.bat`) |
|---|---|---|
| Как выглядит | вкладка в браузере (Chrome/Edge), адресная строка, вкладки | своё окно программы 1600×950, без вкладок и адресной строки |
| Что запускается | uvicorn (`backend`) + dev-сервер CRA (`frontend`) | uvicorn (`backend`) + свой http-сервер статики (`desktop-a\webapp`) + окно pywebview |
| Фронтенд | компилируется на лету dev-сервером | заранее собранная статика (production build) |
| Зависимость от Node.js при запуске | нужен (`npm start`) | **не нужен** |
| Заголовок окна | «React App» (как в `public/index.html`) | «План-Факт» |
| Остановка | `stop.bat` или закрытие окна консоли | закрыли окно → программа завершилась (оба сервера гасятся автоматически) |

Внутри — те же самые серверы и те же самые порты: **бэкенд `:8000`, интерфейс `:3000`**.
Порты закреплены: `frontend/src/config.js` берёт хост из адресной строки, поэтому окно
и другие машины видят один и тот же API, а `GET /` бэкенда отдаёт JSON — окно открывается
на `/index.html`.

По умолчанию серверы слушают **все интерфейсы (`0.0.0.0`)**, то есть программа доступна
и с других компьютеров: окно на этой машине открывается на `http://127.0.0.1:3000`,
а остальные заходят браузером на `http://<адрес этого ПК>:3000`. Адреса для других машин
печатаются при запуске и пишутся в `launcher.log`.

Нужен доступ только с этого компьютера — запустите с ключом `--local-only`
(или задайте `PLANFACT_HOST=127.0.0.1`). Список разрешённых адресов в бэкенде больше
не ведётся вручную: `backend/app.py` сам разрешает localhost, собственные адреса машины,
частные диапазоны и имена машин без домена, поэтому при смене IP ничего править не нужно.

## 2. Как запустить (из исходников)

```
C:\plan-fact-app\desktop-a\start.bat          :: двойной клик — обычный запуск
```

`start.bat` запускает `launcher.py` интерпретатором
`C:\plan-fact-app\.venv-desktop\Scripts\pythonw.exe` (если его нет — `python.exe`).
При запуске с аргументами (например `start.bat --selftest`) скрипт специально
использует `python.exe`, чтобы вывод был виден в консоли.

Оба `.bat`-файла намеренно сделаны **ASCII-only**: русский текст внутри `.bat`
ломает разбор строк `cmd.exe` (проверено — файл в UTF-8 с кириллицей приводил к тому,
что `start.bat` уходил в ветку «Python не найден»). Русские сообщения печатает сам
`launcher.py` — для этого в скриптах стоит `chcp 65001`.

Вручную:

```bat
C:\plan-fact-app\.venv-desktop\Scripts\python.exe C:\plan-fact-app\desktop-a\launcher.py
```

Полезные режимы `launcher.py`:

| Ключ | Что делает |
|---|---|
| *(без ключей)* | поднимает оба сервера и открывает окно |
| `--selftest` | поднимает серверы, проверяет по HTTP `/index.html` и `/health`, печатает результат и выходит (окно не открывает). Код 0 — всё хорошо |
| `--no-window` | то же, но серверы работают до `Ctrl+C` (удобно для отладки; окно не открывается) |
| `--window-test` | открывает окно, убеждается, что оно **реально появилось**, закрывает его и выходит. Код 0 — окно открылось |
| `--window pywebview` | только нативное окно pywebview; если не получилось — понятная ошибка и выход |
| `--window browser` | сразу окно-приложение Edge/Chrome (см. ограничения) |
| `--api-port N`, `--web-port N` | другие порты (для тестов; для обычной работы менять нельзя, см. выше) |
| `--no-reuse` | не переиспользовать уже запущенные на 8000/3000 серверы, а падать с ошибкой |

Диагностика: всё пишется в `desktop-a\launcher.log` (это важно, потому что `pythonw.exe`
не имеет консоли и `print` там не виден). Ошибки запуска дополнительно показываются
модальным окном.

## 3. Как собрать exe

```
C:\plan-fact-app\desktop-a\build_exe.bat
```

* режим **one-dir** (не one-file) — быстрее стартует и надёжнее;
* результат: `C:\plan-fact-app\desktop-a\dist\План-Факт\План-Факт.exe`;
* spec-файл: `planfact.spec`; лог сборки: `build_exe.log`;
* в сборку попадают: `backend/` целиком (как **данные**, вместе с `plan_fact.db`,
  `табель.xlsx`, `Питание.xlsx`), `webapp/` (собранная статика) и
  `ГРАФИК_ФОРМА A3.xlsx` (+ `.backup.xlsx`) из корня проекта;
* exe собирается **без консольного окна** (`console=False`), ошибки показываются
  MessageBox и пишутся в `launcher.log` рядом с exe. Поскольку консоли у exe нет,
  результат проверок смотрите в этом логе: `План-Факт.exe --selftest` вернёт код 0/2,
  а подробности (`✅/❌`, причины ошибок) будут в `dist\План-Факт\launcher.log`.

Почему именно так упаковано (это важно, пути нельзя «переехать»):

| Модуль backend (не менялся) | Как ищет файлы | Что положено в сборку |
|---|---|---|
| `database.py` | `DB_PATH` = `<папка backend>/plan_fact.db` (относительно своего файла) | `_internal/backend/plan_fact.db` |
| `export_timesheet.py` | `os.path.dirname(__file__)/табель.xlsx` | `_internal/backend/табель.xlsx` |
| `schedule_grid.py` | `ROOT_DIR` = **родитель** `backend/`, файл `ГРАФИК_ФОРМА A3.xlsx` | `_internal/ГРАФИК_ФОРМА A3.xlsx` |

`launcher.py` подхватывает `backend/` через `sys.path` (модули лежат на диске как
данные, а не внутри архива) — поэтому все `__file__`-относительные пути внутри
`backend/` продолжают работать так же, как при запуске из исходников.

Статику фронтенда можно пересобрать в любой момент, не задевая `frontend/build`
(он и не создаётся — сборка идёт через `BUILD_PATH`):

```powershell
cd C:\plan-fact-app\frontend
$env:BUILD_PATH='C:\plan-fact-app\desktop-a\webapp'; npm.cmd run build
```

## 4. Что переиспользуется без изменений

* `backend/` — весь FastAPI-бэкенд, включая `plan_fact.db`, шаблоны `табель.xlsx` и
  `Питание.xlsx`, модули `schedule_grid.py`, `parse_*.py`, `plan_fact_export.py`.
  Изменений в коде — ноль. Бэкенд поднимается в потоке основного процесса
  (`uvicorn.Server`), а не отдельным `uvicorn.exe`;
* `frontend/` — исходники React, из них собирается **свой** экземпляр статики в
  `desktop-a\webapp` (production build; CRA использует `BUILD_PATH`, поэтому
  `frontend\build` не создаётся и не перезаписывается);
* `ГРАФИК_ФОРМА A3.xlsx` из корня проекта (нужен `schedule_grid.py`);
* сам `start.bat`/`stop.bat` веб-версии не трогаются — обычный запуск продолжает работать.

Единственная «правка» данных, которую делает прототип: в **своей копии**
`desktop-a\webapp\index.html` заголовок `<title>React App</title>` заменяется на
`<title>План-Факт</title>` (чтобы окно называлось «План-Факт»). Файлы `frontend/` при
этом не изменяются.

## 5. Честные ограничения прототипа

1. **Внутри всё ещё работают локальные порты 8000 и 3000.** Снаружи это не видно, но:
   * если рядом запущена обычная веб-версия (`start.bat`), прототип **обнаружит** занятые
     порты и честно напишет об этом. Если на 8000 отвечает `/health`, а на 3000 отдаётся
     `/index.html`, прототип **переиспользует** эти серверы (свой бэкенд не поднимает) —
     окно откроется, но покажет dev-сервер веб-версии, а не собранную статику
     `desktop-a\webapp`. Чтобы увидеть именно прототип, закройте веб-версию (`stop.bat`);
   * если порт занят чем-то посторонним — понятная ошибка, выход с кодом 2. Чужие
     процессы прототип **не** завершает намеренно;
   * сменить порты для обычной работы нельзя (хост берётся из адресной строки, порт API
     закреплён в `frontend/src/config.js`). Ключи `--api-port/--web-port` — только для тестов;
   * сетевой режим (по умолчанию) открывает порты 8000 и 3000 для всей сети: при первом
     запуске Windows может спросить разрешение в брандмауэре — его нужно разрешить.
     Если доступ из сети не нужен, запускайте с `--local-only`.
2. **Окно зависит от pywebview → pythonnet → WebView2.** Основной путь — нативное окно
   pywebview (WebView2 Runtime в системе есть, v153). pywebview запускается в
   **отдельном дочернем процессе**: если pythonnet/WebView2 падает, основной процесс с
   серверами не страдает, а прототип переходит к резервному варианту.
   Резервный вариант — отдельное окно Edge/Chrome в режиме `--app` (тоже без вкладок и
   адресной строки, движок тот же Chromium, но формально это браузер). Он требует
   установленного Edge или Chrome и, в ограниченных средах, уже запущенного браузера
   (тогда окно открывает его процесс). Если не сработало ни то, ни другое — модальное
   сообщение об ошибке и ненулевой код, а не молчаливый белый экран.
3. **Размер дистрибутива.** exe тянет за собой pandas/numpy/openpyxl/xlrd/uvicorn и всю
   статику фронтенда: папка `dist\План-Факт` занимает **≈90 МБ** (908 файлов),
   сам `План-Факт.exe` — ≈16 МБ. Папку нужно переносить целиком (это one-dir),
   один exe без соседней папки `_internal` не работает.
4. **Запись рядом с программой.** В `_internal\backend\plan_fact.db` ведётся своя копия
   базы: данные, введённые в exe, **не попадают** в `backend\plan_fact.db` проекта, и
   наоборот. Поэтому exe нельзя класть в `Program Files` или в папку только для чтения —
   нужна запись (БД, шаблоны выгрузок, профиль резервного окна `.webprofile`).
5. **Статика — снимок.** `webapp/` — это сборка на момент сборки. Изменили фронтенд —
   нужно пересобрать `webapp` (команда выше) и заново собрать exe.
6. **Нет подписи кода** — Windows SmartScreen может предупредить при первом запуске exe.
7. **Один экземпляр.** Второй запущенный прототип упрётся в занятые порты (см. п. 1);
   окна двух экземпляров одновременно не будет.
8. **Резервное окно и его профиль.** Для окна-приложения Edge/Chrome создаётся папка
   `desktop-a\.webprofile`. Она небольшая, но её можно удалять — при следующем запуске
   создастся заново.
9. **Эмодзи/русский текст в консоли.** `start.bat` делает `chcp 65001`, сам launcher
   переключает stdout на UTF-8; при запуске через `pythonw.exe` консоли нет вообще —
   смотрите `launcher.log`.

## 6. Что именно проверено запуском

**Из исходников (`launcher.py`):**

* `--selftest` → код 0, напечатано, что `index.html` отдан (200) и бэкенд жив (`/health` 200).
  В проверочной среде порты 8000/3000 были заняты запущенной веб-версией, поэтому здесь
  сработал режим переиспользования; отдельно, на свободных портах
  (`--api-port 18000 --web-port 13000`), проверены **свои** серверы: свой uvicorn на базе
  `backend/app.py` отвечал `/health` (200), `/employees` (8155 байт) и `/plan-fact/`
  (319 707 байт — то есть pandas + `schedule_grid.py` + чтение `ГРАФИК_ФОРМА A3.xlsx`),
  а свой сервер статики отдавал `index.html`, css/js, делал SPA-fallback (200 на
  неизвестный путь без расширения) и 404 на несуществующий файл ассета;
* `--no-window` → серверы живут, отдают данные, гасятся по `Ctrl+C`;
* `--window-test` → окно реально открывается (найдено через Win32 `EnumWindows` по
  заголовку и закрыто автоматически), код 0. Проверено и на своём статике: заголовок
  окна «План-Факт»;
* нативный pywebview в проверочной среде поднять не удалось (pythonnet не может
  инициализироваться: `Failed to initialize Python.Runtime.dll`, `OpenProcess → отказано
  в доступе`; Qt WebEngine там падает так же — ограничение песочницы, а не кода).
  Код этот сбой корректно обрабатывает: дочерний процесс сообщает об ошибке, она
  записывается в лог, серверы не страдают, прототип переходит к резервному окну.
* **нативный pywebview проверен отдельно — он работает.** Тот же самый
  `--window-test --api-port 18000 --web-port 13000 --no-reuse`, запущенный без ограничений
  проверочной песочницы, открыл окно именно через pywebview:
  `WINDOW TEST: OK — pywebview: ok: hwnd=9503562, заголовок «План-Факт»` (код 0).
  Значит, падение pythonnet — артефакт песочницы, а не кода: на обычном рабочем столе
  `start.bat` открывает настоящее нативное окно WebView2, а резервный вариант с
  Edge/Chrome `--app` нужен только на случай сбоя pythonnet или отсутствия WebView2.

**Собранный exe (`dist\План-Факт\План-Факт.exe`):**

* `--selftest` (порты по умолчанию, занятые веб-версией) → код 0, переиспользование
  существующих серверов;
* `--selftest --api-port 18000 --web-port 13000` → код 0: exe **сам** поднял бэкенд из
  `_internal\backend` и статику из `_internal\webapp`;
* `--no-window --api-port 18000 --web-port 13000` → реальные данные из сборки:
  `/health` 200, `/employees` 200 (8155 б), `/plan-fact/?year=2026&month=8` 200 (319 707 б,
  чтение `_internal\ГРАФИК_ФОРМА A3.xlsx`), `/export/timesheet/` 200 (40 390 б, шаблон
  `_internal\backend\табель.xlsx`), `/timesheet/` 200 (123 739 б); статика 200, SPA-fallback
  200, отсутствующий ассет 404; в логе ошибок нет;
* `--window-test` → код 0, окно открылось (через резервный вариант) и закрылось.
  Отдельно проверено, что изоляция работает и в exe: дочерний процесс — это сам
  `План-Факт.exe` с ключом `--window-only`.

**Скрипты запуска:**

* `start.bat` без аргументов → поднимает launcher через `pythonw.exe` (без консоли),
  окно открывается, launcher живёт; закрытие окна → оба процесса launcher завершаются,
  в логе появляются «Окно закрыто — завершаю работу» и «Прототип … завершён»;
* `build_exe.bat` → полная сборка с нуля (папки `build`/`dist` пересоздаются), лог
  сборки — `build_exe.log`.

Итог: пути внутри сборки не «поехали» — БД, шаблоны и файл графика находятся сборкой
там, где их ожидает неизменённый код `backend/`.

## 7. Состав папки

```
desktop-a\
  launcher.py        — точка входа прототипа (серверы + окно + режимы проверки)
  start.bat          — обычный запуск (pythonw.exe)
  build_exe.bat      — сборка exe (PyInstaller)
  planfact.spec      — spec-файл сборки (one-dir, данные backend/webapp/xlsx)
  webapp\            — собранная статика React (BUILD_PATH из frontend)
  README.md          — этот файл
  launcher.log       — лог последнего запуска (создаётся при работе)
  build\, dist\      — результаты сборки exe (создаются build_exe.bat)
  .webprofile\       — профиль резервного окна Edge/Chrome (создаётся при работе)
```
