# Настольный «План-Факт» (вариант Б) — PySide6 поверх существующего ядра

То же приложение, что и веб-версия, но **нативное окно** (Qt), без браузера,
без HTTP и без портов. Вид и поведение приведены к веб-версии: цвета, шрифты,
шапки таблиц, кнопки, легенды и тексты сообщений взяты из её исходников.

## Запуск

```
run.bat                        # обычный запуск, без окна консоли
run-console.bat                # с консолью: видно сообщения ядра и ошибки
run.bat --selftest             # проверка без диалогов: грузит все вкладки, код 0/1
run.bat --year 2026 --month 9  # открыть конкретный период
```

Интерпретатор берётся из `..\.venv-desktop\Scripts\pythonw.exe`
(если его нет — из `PATH`). В этом venv стоят зависимости проекта + PySide6.

## Сборка exe

```
build_exe.bat
```

Результат: `dist\План-Факт\План-Факт.exe` (one-dir — папку переносить целиком).
Окно консоли у сборки нет, поэтому и ошибки, и отчёт `--selftest` пишутся
в `planfact-desktop.log` рядом с exe.

Данные при первом запуске копируются рядом с программой, чтобы базу и книгу
графика можно было править, а пересборка их не затирала:

```
dist\План-Факт\
    План-Факт.exe
    planfact-desktop.log
    backend\plan_fact.db          ← рабочая база
    backend\табель.xlsx           ← шаблон формы Т-13
    ГРАФИК_ФОРМА A3.xlsx          ← рабочая книга графика
    ГРАФИК_ФОРМА A3.backup.xlsx
    _internal\...                 ← код, библиотеки и seed\ с исходными данными
```

## Как это устроено

**Бизнес-логика не переписана.** Приложение вызывает те же функции, что и
веб-версия, но напрямую — в своём процессе:

| Что | Откуда |
|---|---|
| План-факт, табель, статистика, правка ячеек | `backend/planfact_service.py` |
| Сетка графика А3 и действия по ней | `backend/schedule_grid.py` |
| Табель Т-13 (xlsx) | `backend/export_timesheet.py` |
| Загрузка журнала СКУД и графика | `backend/parse_journal.py`, `parse_schedule.py` |
| База | `backend/database.py` (тот же `plan_fact.db`) |

**FastAPI в рантайме не участвует.** Раньше логика чтения данных и сборки
выгрузок жила прямо в эндпоинтах `app.py`, и настольная версия вынуждена была
импортировать его вместе со всем веб-стеком. Логика вынесена в сервисный слой
`backend/planfact_service.py`; в `app.py` осталось только описание HTTP
(пути, коды, заголовки). Проверка: при импорте `planfact.core` в `sys.modules`
нет ни `fastapi`, ни `starlette`, ни `pydantic`, ни `uvicorn`.

Файлы прототипа:

```
desktop-b\
  run.py                   точка входа (аргументы, журнал, показ фатальных ошибок)
  run.bat / run-console.bat
  build_exe.bat, planfact-b.spec
  make_screenshots.py      снимки вкладок средствами Qt → screenshots\
  ДИЗАЙН_СПЕЦ.md           спецификация вида, снятая с frontend/src
  planfact\
    core.py                мост к ядру: все данные и действия без HTTP
    frozen.py              пути к данным в собранном exe
    gui\
      theme.py             палитра и шрифты из веб-версии
      widgets.py           шапка-вкладки, выбор месяца, строки сообщений, легенда
      common.py            состояние, ячейки, вид таблиц, правка времени
      main_window.py       каркас окна
      planfact_tab.py      «План-Факт» (матрица)
      timesheet_tab.py     «Табель» (Т-13)
      meal_tab.py          «Питание»
      schedule_tab.py      «График» (форма А3)
```

## Что воспроизведено из веб-версии

* **Каркас**: шапка `◀ [Сентябрь 2026] ▶`, вкладки-кнопки `📊 План-Факт`,
  `📋 Табель`, `🍽️ Питание`, `📅 График` (активная — своим цветом), справа
  `📤 Журнал`, `📤 График`, `🔄 Обновить`, ниже — цветная строка сообщений
  (успех `#d4edda`, ошибка `#f8d7da`, предупреждение `#fff3cd`).
* **«План-Факт»**: матрица «сотрудник × дни месяца × 5 подколонок»
  (План / Приход / Уход / Факт / Этапы), закреплённые слева `№/ФИО/Должность`,
  двухъярусная синяя шапка, кнопки недель со счётчиками, сортировка по ФИО и
  должности, `📥 Неделя`, `📥 Месяц`, `🗑️ Удалить (…)`, легенда статусов,
  правка ячеек по клику (маска ЧЧ:ММ, Enter/Esc/уход фокуса).
* **«Табель»**: две строки на сотрудника (коды явок и часы), строка-разделитель,
  половины месяца I/II, итоги `Дни I / Часы I / Дни II / Часы II / Дни всего /
  Часы всего`, легенда кодов, сортировка, `◀ Назад`, выгрузка XLSX в фоне.
* **«График»**: все шесть действий (`📄 Создать лист`, `🗑️ Удалить из графика`,
  `📥 Как есть`, `📥 Только ритмы`, `⚙️ Расставить смены`, `🧹 Очистить`),
  панель добавления сотрудника, счётчики сверки, четыре вида рамок сверки,
  легенда цветов и рамок, правка ячеек.
* **«Питание»**: заголовок, дата, `🔍 Показать сотрудников`, кнопки
  `🌅 Кафе утро (165 руб.)` и `🍽️ Обед (460 руб.)`, нумерованный список,
  счётчик `👥 N чел.`.

Полная спецификация вида — в `ДИЗАЙН_СПЕЦ.md` (все значения со ссылками на
исходники фронтенда).

## Осознанные отличия от веб-версии

1. **Переключатель `✏️ Правка` / `✏️ Разрешить правку`.** В вебе правка ячейки
   сразу пишет в базу и в файл графика. Здесь правка по умолчанию **выключена**,
   чтобы случайный клик не испортил рабочие данные; включается одной кнопкой.
2. **Нет переноса строк в панелях** (`flex-wrap`): в Qt нет flow-layout,
   поэтому панели занимают одну строку (при необходимости — две внутри панели).
3. **Нет закрепления строк шапки листа и первых колонок «Графика»**
   (`position: sticky` в вебе): `QTableWidget` этого не умеет. В «План-Факте»
   закрепление сделано отдельными синхронизированными таблицами.
4. Диалоги — нативные `QMessageBox` вместо браузерных `window.confirm`.
5. Часть служебных мелочей веба (баннер тестовых данных, автоподстановка
   тестовых сотрудников при недоступном API) не переносилась.

## Что проверено

* `run.py --selftest` → код 0; вкладки: план-факт 50 строк, табель 156,
  график 55, питание 31 — на реальных данных проекта.
* Сервисный слой: снимок API до и после выноса логики — **19 из 19 эндпоинтов
  совпали по содержимому** (сравнение JSON по данным и xlsx по содержимому
  архивов, без служебных `docProps`). Отдельно проверено, что порядок ключей
  у `/employees`, `/plans`, `/facts` меняется от запуска к запуску и раньше —
  это свойство самого FastAPI, а не следствие переноса.
* Операции правки (`update_time`, `update_plan`, `update_production_stage`,
  `delete_employee_from`) — 21 проверка на **копиях** базы и файла графика:
  что вернул вызов, что стало в базе, тексты сообщений и коды ошибок.
* Табель: 1560 ячеек и все итоги сверены с сырыми данными ядра — расхождений 0.
* План-факт: переключение недель, сортировка, геометрия закреплённых колонок и
  шапки, цвета ячеек — проверены; в базу при проверках ничего не записано.
* График: рамки сверки и заливки проверены попиксельно; «правка» проверена
  с подменёнными функциями ядра — реальный файл не изменялся.

Скриншоты: `screenshots\` (снимаются `make_screenshots.py`).

## Честные ограничения

* Одна общая база с веб-версией: если запущена и веб-версия, и настольная,
  они работают с одним `backend/plan_fact.db` (одновременная правка не
  блокируется — SQLite, как и раньше).
* Дистрибутив ~150–200 МБ (Qt + pandas + openpyxl), без подписи кода —
  возможен предупреждение SmartScreen при первом запуске.
* Правка ячеек «в бою» не проверялась: автотесты проверяли валидацию и гейты,
  но не записывали в реальные данные.
