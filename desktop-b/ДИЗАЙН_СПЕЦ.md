# ДИЗАЙН-СПЕЦИФИКАЦИЯ «План-Факт» — веб-версия → PySide6

Документ снят **только с исходников веб-фронтенда** (`C:\plan-fact-app\frontend\src`).
Каждое значение сопровождается ссылкой `файл:строка`. Если значение в коде не найдено —
написано «по умолчанию». Никаких догадок о внешнем виде не добавлялось.

Источники:

| Файл | Что из него взято |
|---|---|
| `frontend/src/App.js` | каркас страницы, панель действий, состояние, загрузки, удаление |
| `frontend/src/constants.js` | палитра статусов, названия месяцев/дней/недель |
| `frontend/src/index.css` | шрифт и фон `body` |
| `frontend/src/components/Header.js` | верхняя панель (общая для всех вкладок) |
| `frontend/src/components/MonthSelector.js` | переключатель месяца |
| `frontend/src/components/PageTabs.js` | вкладки |
| `frontend/src/components/UploadButtons.js` | загрузка «Журнал» / «График» |
| `frontend/src/components/MessageBar.js` | цветная строка сообщения |
| `frontend/src/components/Legend.js` | легенда статусов |
| `frontend/src/components/PlanFactTable.js` | таблица план-факта |
| `frontend/src/components/ScheduleView.jsx` | вкладка «График» (форма А3) |
| `frontend/src/Timesheet.js` | вкладка «Табель» |
| `frontend/src/MealExport.jsx` | вкладка «Питание» |
| `frontend/src/hooks/useCellEditing.js` | логика правки ячеек план-факта |
| `frontend/src/config.js` | базовый адрес API |

**Важно про стек.** Material UI в коде **не используется** (в `index.js:1-11` нет `ThemeProvider`
и `@mui`), весь вид задан инлайновыми `style={{...}}`. Поэтому «цвета темы MUI» в проекте
отсутствуют — все цвета ниже это буквальные HEX из исходников.

## 4. Вкладка «План-Факт»

### 4.1 Данные

* Источник: `GET {API_URL}/plan-fact/?year=YYYY&month=MM` (`App.js:59`).
  `API_URL` = `http://127.0.0.1:8000` на localhost, иначе `http://{hostname}:8000` (`config.js:2-12`).
* Перезагрузка при смене месяца и по кнопке «Обновить» (`App.js:71-73`).
* Каждая строка ответа: `employee_name`, `department`, `position`, `date`, `plan_type`,
  `plan_hours`, `fact_hours`, `status`, `start_time`, `end_time`, `production_stage`
  (`App.js:184-192`).
* Записи группируются по неделям по **числу месяца**: 1–7 → неделя 0, 8–14 → 1, 15–21 → 2,
  22–28 → 3, 29–31 → 4 (`App.js:149-168`). На экран выводится только текущая неделя.
* Внутри недели сотрудники группируются по `employee_name` (`App.js:173-193`);
  колонки-даты — уникальные даты недели, отсортированные по возрастанию (`App.js:208`).
  **Дней без записей в таблице нет вообще.**
* Сортировка клиентская, по строке в нижнем регистре: поля `name` (ФИО) и `position`
  (Должность); по умолчанию поле `name`, направление `asc` (`App.js:43-44,195-217`).
  Иконка состояния: `↕` (не сортируется по этому полю), `↑` (по возрастанию), `↓` (по убыванию)
  (`App.js:418`).

    (`useCellEditing.js:19-24,173-175`);

* Поля `План` и `Этапы` сохраняются на blur/Enter без валидации
  (`useCellEditing.js:181-197`).

* Эндпоинты: `POST /update-time/` (`{employee_name, date, field, value}`),
  `POST /update-production-stage/` (`{employee_name, date, value}`),
  `POST /update-plan/` (`{employee_name, date, value}`) — `useCellEditing.js:42,64,85`.
* После успешного сохранения список план-факта перезагружается (`onSaved → loadData`,

  строки (`useCellEditing.js:14-16,26-32`).
* Ячейка `Факт` не редактируется вообще (обработчика клика нет, `PlanFactTable.js:405-416`).

### 5.7 Редактирование в графике

* Клик по ячейке с `editable`: если у строки есть сотрудник, строка сначала выделяется

* `Enter` — сохранить; `Escape` — отменить (без записи); уход фокуса — сохранить.
  После `Enter` повторное сохранение по blur подавляется флагом `handledRef`
  (`ScheduleView.jsx:67,344-369`).
* Поля `ef` (`name`, `position`, `section`) уходят в `POST /schedule/employee/update/`
  `{row, field, value, year, month}`; все прочие — в `POST /schedule/cell/`
  `{row, col, value, year, month}` (`ScheduleView.jsx:115-135`).
* После сохранения: сообщение `✅ {message сервера}` / `❌ {detail}`, перезагрузка сетки и
  обновление план-факта (`ScheduleView.jsx:126-135`).
* Выделение строки хранится как `{row, name}` (номер строки **и** ФИО), чтобы не сбрасываться
  при перезагрузке и не путать однофамильцев (`ScheduleView.jsx:39-41,79-84`).

## 9. Что в веб-версии сделано «хитро» и что нельзя потерять

1. **Закрепление строк и колонок план-факта.** Шапка липнет на `top: 0` и `top: 34px`,
   первые три колонки — на `left: 0 / 24px / 124px` с разными `z-index` (4 в шапке, 1 в теле)
   (`PlanFactTable.js:50,56-62,113-120,201-206`).
2. **Статус красит не только «свою» ячейку.** В план-факте цвет статуса наносится на фон
   ячейки **«План»** (`PlanFactTable.js:289`), а «Факт» получает свой фон `#e3f2fd`
   при `> 0` (`PlanFactTable.js:411`). Отдельной колонки «Статус» в веб-таблице **нет**.
3. **Объединение «5 колонок на день».** Каждая дата занимает группу из 5 подколонок
   с `colSpan="5"` в шапке (`PlanFactTable.js:97-111`).
4. **`rowSpan="3"` при двух строках шапки** — см. предупреждение в п. 4.3.
5. **Адаптивный размер.** Ширина колонок и базовый размер шрифта зависят от количества дней
   на экране (`App.js:316-318`), а размеры отдельных ячеек считаются через `Math.max(...)`
   от базового (`PlanFactTable.js:199,216,236,292,331,408,421`).
6. **Выделение строки живёт по ФИО, а не по индексу** — сохраняется после перезагрузки,
   сортировки и правки (`useCellEditing.js:14-16`; в «Графике» — `{row, name}`,
   `ScheduleView.jsx:39-41`).
7. **Автопрокрутка к выбранному сотруднику** только если строка вне видимой области
   (`PlanFactTable.js:29-33`).
8. **Правка одним кликом** (а не двойным) в план-факте: клик по ячейке сразу открывает поле
   ввода с текущим значением (`PlanFactTable.js:299`; `useCellEditing.js:103-108`).
9. **`Escape` в план-факте снимает и правку, и выделение сотрудника**
   (`useCellEditing.js:19-24,173-175`) — в легенде это подписано как «отмена».
10. **Маска времени `ЧЧ:ММ`** с автодобавлением двоеточия и ограничением в 5 символов
    (`useCellEditing.js:110-125`) и регулярная проверка при сохранении
    (`useCellEditing.js:5,163,199`).
11. **Подавление двойного сохранения в «Графике»**: после `Enter` blur уже не пишет второй раз
    (`ScheduleView.jsx:67,344-369`). В Qt аналог — флаг «сохранено по Enter».
12. **Рамки сверки через `inset box-shadow`**, а не через `border` — они не меняют размер
    ячейки и не сдвигают сетку (`ScheduleView.jsx:7-12,392`).
13. **Рамки сверки не заменяют заливку**: заливка из Excel сохраняется, рамка рисуется поверх
    (`ScheduleView.jsx:373-377,392`).
14. **Закрепление первых трёх колонок в «Графике»** на `left: 0/104px/268px`
    (`ScheduleView.jsx:15-16,901-908`) и липкая шапка из двух строк (`top: 0` и `top: 18px`,
    `ScheduleView.jsx:893-900`).
15. **Объединённые ячейки графика** из `merges` с `rowSpan`/`colSpan` и высотой
    `rows × 18px`; «накрытые» ячейки вообще не создаются (`ScheduleView.jsx:300-309,394,915-916`).
16. **Выходной в «Графике» определяется календарём месяца**, а не данными файла
    (`ScheduleView.jsx:371-377`; заливка `#73A0B4` по умолчанию, `ScheduleView.jsx:315`).
17. **Колонки-дни графика тянутся**, а служебные и закреплённые — фиксированы, при
    `min-width: 980px` у таблицы (`ScheduleView.jsx:331-335,855-858`).
18. **Диалог очистки с автоотменой через 5 секунд** и обратным отсчётом в подписи
    (`ScheduleView.jsx:63,96-108,800-803`).
19. **Удаление строки из графика не трогает план в базе** — диалог прямо объясняет это и
    отсылает к кнопке `🗑️ Удалить (неделя)` на план-факте (`ScheduleView.jsx:598-601`).
20. **Каждая правка графика перезагружает план-факт** через `onPlanChanged`
    (`ScheduleView.jsx:128,153,190,236,282`; `App.js:374`).
21. **Табель рисует по две строки на сотрудника** плюс строку-разделитель 4px, делит месяц на
    половины I/II с колонкой-разделителем (`Timesheet.js:238-239,590-786`).
22. **Табель умеет показывать тестовые данные** вместо пустого экрана при недоступном API
    (`Timesheet.js:110-141`) — это осознанное поведение, а не заглушка на один запуск.
23. **Смена месяца общей шапкой управляет всеми вкладками сразу**; неделя план-факта
    сбрасывается на первую (`App.js:108,114`).
24. **Кнопка `🔄 Обновить` в шапке работает через счётчик загрузок** и заставляет перезагрузиться
    активную вкладку (`App.js:50,75-77`).
25. **Разнобой в правах на правку:** в план-факте правка всегда доступна, а вкладка «График»
    пишет прямо в файл Excel — поэтому там есть предупреждающие `title` у каждой кнопки.
26. **Вкладка «Питание» подменяет ФИО** и исключает сотрудников по списку
    (`MealExport.jsx:15-17`) — это часть бизнес-логики, её нельзя терять при переносе.
27. **Выгрузка питания может вернуть JSON-предупреждение** вместо файла — фронтенд проверяет
    `content-type` (`MealExport.jsx:141-150`).
28. **Список питания печатается в две колонки** (`gridTemplateColumns: '1fr 1fr'`),
    а не одной (`MealExport.jsx:317-321`).

### 11.8 Общие системные расхождения

1. **Насыщенность/размеры шрифтов не заданы.** В desktop-b нет ни одного `setFont`/`setStyleSheet`
   со шрифтом — берётся системный; в вебе размеры 7–12px для таблиц и 9–17px для остального
   (см. раздел 2). Следствие — строки таблиц desktop-b выше: `row_height=19` в графике,
   `21` в план-факте, `32` в табеле (`schedule_tab.py:57`, `planfact_tab.py:53`,
   `timesheet_tab.py:64`), тогда как в вебе ячейки план-факта — это фактически 1 строка
   ~14–16px с `padding: 1px 1px`.
2. **Цвета шапок таблиц.** В вебе шапка план-факта — `#1565c0` с белым текстом и границами
   `#0d47a1`, подзаголовки — `#e3f2fd`/`#0d47a1`/границы `#90caf9`; шапка табеля — `#d9d9d9`
   с выходными `#d4edda`. В desktop-b цвета шапок не задаются вовсе.
3. **Состояния загрузки.** В вебе есть текстовые индикаторы `🔄 Загрузка данных...`,
   `🔄 Загрузка графика…`, `🔄 Загрузка табеля...`, `⏳ обновление…`; в desktop-b — только
   `WaitCursor` и однократная загрузка вкладки на период (`main_window.py:183-193`).
4. **Сообщения об успехе.** В вебе каждое действие заканчивается цветной строкой с текстом
   (см. разделы 4.6, 5.9, 6.5, 7); в desktop-b тексты собираются в `statusBar`
   без цветовой кодировки (`main_window.py:291-292`), а результаты загрузки файлов выводятся
   модальным `QMessageBox.information` с текстом `Готово` (`main_window.py:229`).
5. **Пустые состояния.** В вебе расписаны дословные тексты для пустого списка на трёх вкладках
   (`App.js:386-404`, `Timesheet.js:195-207`, `ScheduleView.jsx:104`); в desktop-b пустое
   состояние рисуется как пустая таблица плюс красная подпись об ошибке.
6. **Панели-подсказки.** В вебе у каждой кнопки и ячейки есть дословные `title`; в desktop-b
   `tooltip` есть только у ячеек графика и трёх кнопок (`schedule_tab.py:125-136`,
   `main_window.py:104,109`, `schedule_tab.py:34-37`).
