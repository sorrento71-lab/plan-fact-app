# Восстановление истории чатов DSH по проекту «План-Факт»

Дата: 18.09.2026. Хост: приложение DeepSeek Harness, `dsh-home` = `%APPDATA%\DeepSeek Harness\dsh-home`.

## Симптом

В боковой панели старые чаты проекта `C:\plan-fact-app` видны, но при открытии пустые.
Затронуты оба главных чата проекта:

- `session-98287012-…` — «ты прочитал папку с мо…» (25.08–15.09, 10.9 МБ);
- `session-8d3180ee-…` — «Создание проекта как отдельной программы» (26.08–16.09, 3.1 МБ);
- плюс 6 под-агентских сессий от 16.09 (`Rewrite schedule/timesheet/meal/plan-fact tab`, `Build desktop variant A`, `Extract web UI design spec`).

## Причина

Ничего не удалялось: все `session.jsonl.zstd` лежали на диске целиком. Сломалась **читаемость** после
обновления приложения 17.09.2026 14:31 на harness `0.1.6-alpha.1` (`f9c7d9178383adfd`).

Старые чаты записаны в формате **поколения v0** (`"version":0` в заголовке, файл `session.jsonl.zstd`) версией
harness `6f6390b843ed781c` (27.08). Новый backend сессий читает только «канонические» имена поколений
(`session.jsonl.zstd` = v0, `session.vN.jsonl.zstd` = vN+) и прогоняет старый лог через миграцию v0→v1→v2→v3.
Миграция падала на первой же строке события:

```
SessionFormatUnsupportedMigrationError: @deepseek-ai/dsh-session-format-v0-to-v1 refuses this format v0 Session:
  permission/preset 0 data has unexpected member "origin"
    (файл: packages/session/session-format-v0-to-v1/lib/index.js, RELEASED_V0_EVENT_DISPOSITIONS)
```

Освобождённый («released») v0-кодек в новой версии знает для события `permission/preset` только член `preset`,
а версия 27.08 писала ещё и `origin: "default"`. Ошибка не выводится в интерфейс, поэтому чат выглядит просто пустым.
Под-агентские логи падали на второй несовместимости: `subagent/descriptor 0 uses unsupported descriptor version 2`
(кодек требует `version: 3`).

## Что сделано

Старые логи сконвертированы в текущее поколение **v3** тем же кодом, которым это делает само приложение
(`session-format-catalog` из установленного harness), и рядом с оригиналами положены файлы
`session.v3.jsonl.zstd`. Backend выбирает старшее поколение в каталоге сессии, поэтому теперь читается v3,
а исходные `session.jsonl.zstd` остались нетронутыми (их можно удалить вручную — они больше не используются).

При конвертации потребовались ровно две нормализации несовместимых полей:

| Что | Сколько | Смысл |
|---|---|---|
| `permission/preset`: удалён член `origin` | 1 строка на главную сессию | дублировал источник пресета, на содержимое чата не влияет |
| `subagent/descriptor`: `version` 2 → 3 | 1 строка на под-агентскую сессию | набор полей уже полностью совпадал со схемой v3 |

Установлено 15 файлов (по одному на каждую старую сессию, включая чаты других проектов):

```
--C-airtime--          1   --C-plan-fact-app--  8   (2 главных + 6 под-агентских)
--C-bot--              1   --C-pro-plan--        4   (1 главный + 3 под-агентских)
--C-bot2--             1
```

## Проверка

1. Каждый сконвертированный артефакт перечитан тем же каталогом форматов: `readHeader` = `current` (v3),
   число событий совпадает с миграцией, `id`/`cwd` не изменились.
2. Сверка содержимого: число событий `user/message` в v0 и v3 совпадает во всех сессиях
   (например, 71=71 и 24=24 в главных чатах проекта). Уменьшение общего числа событий ожидаемо:
   v3 склеивает потоковые `reasoning-chunks`/`assistant/chunk`/`text-chunks` в цельные сообщения.
3. `verify-all.mjs` обошёл все 17 каталогов сессий как это делает backend (старшее поколение + чтение заголовка):
   `readable=17 problematic=0`.

## Файлы

| Файл | Назначение |
|---|---|
| `convert-v0.mjs` | конвертер v0 → v3: `node convert-v0.mjs --in <session.jsonl.zstd> --out <session.v3.jsonl.zstd> [--harness <dir>]`. Оригинал не изменяет, сам проверяет результат перечитыванием. |
| `verify-all.mjs` | аудит всех сессий DSH: `node verify-all.mjs`. Показывает, какие каталоги резолвятся в читаемое поколение. |
| `convert-log.txt` | полный протокол конвертации всех 15 сессий. |

## Если повторится после следующего обновления

Симптом тот же: чат в списке есть, открывается пустым. Диагностика одной командой:

```powershell
node C:\plan-fact-app\tools\dsh-history-restore\verify-all.mjs
```

Строки, отличные от `ok`, — это сессии, которые текущая версия приложения не читает; для них повторяется
процедура конвертации. Все текущие сессии теперь в v3, поэтому следующее обновление должно мигрировать их
штатно — v3 является релизным форматом, и миграция v3→vN выполняется самим приложением.

## Ограничения

- Сообщения не переписывались: конвертация — это переупаковка той же истории в новый формат.
- Потеряны только служебные поля, перечисленные в таблице нормализаций (на отображение чата не влияют).
- Старые файлы v0 оставлены на месте как исходники; при желании их можно удалить, освободив ~28 МБ.
